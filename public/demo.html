Review record

Accepted with a note

Each stored claim entered the normal review service as pending. The seed command records an explicit acceptance note only after checking the quotation and date precision against the captured source.

Year-only commitments are shown as a year. SS Tool does not turn “2033” into an invented calendar day. A policy without a dated end is shown as a policy, not as a confirmed end date.

How it works

From catalogue record to public support information.

These are the real stages of the product. This demo exposes their stored result, not a simulation of each operation.

  1. 01

    Product catalogue

    A retailer records the manufacturer, product name and model identifier.

    Stored for each demo product
  2. 02

    Source discovery

    The manufacturer's support page is retrieved and stored with its URL and capture time.

    One Fairphone support article stored
  3. 03

    AI-assisted extraction

    In the private workflow, AI can propose a claim only with a verbatim quotation.

    Not run by this demo
  4. 04

    Human verification

    A reviewer checks the source, quotation, date precision and conflicts, then accepts or rejects with a note.

    3 accepted review records
  5. 05

    Public support information

    The public API publishes only accepted evidence and recalculates the support status on request.
